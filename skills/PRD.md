# 日语唰唰唰 PRD

**版本：MVP v1.0**  
**用途：后续 UI、Flutter、数据结构与功能开发的统一需求依据**

> 规则：本文档只记录已确认的产品需求和开发约束。未写入本文档的功能，不属于 MVP 必做范围。

---

# 1. 产品目标

## 1.1 核心问题

目标用户通常已经具备一定日语基础，但存在：

- 看得懂，却说不出来
- 知道中文意思，却无法快速检索日语
- 会单词，却不会自然组合成句子
- 考试能力较强，但日常主动表达能力不足

## 1.2 产品目标

通过高频、短时、主动输出训练，把：

**“认识但说不出来的日语”**

转化为：

**“看到场景后能够主动说出来的日语”。**

## 1.3 核心学习闭环

```text
场景 / 图片
    ↓
中文提示
    ↓
日语不完整句
    ↓
用户主动回忆
    ↓
按住麦克风说话
    ↓
语音识别
    ↓
答案判断
    ↓
正确 / 错误反馈
    ↓
显示标准答案
    ↓
播放标准语音
    ↓
唰下一张
```

## 1.4 产品定位

**轻量、快速、语音优先、以主动表达为核心的日语训练 App。**

# 2. 使用场景

## 2.1 日常生活

用户通过真实生活场景练习常用表达，例如：

- 家里
- 超市
- 餐厅
- 电车
- 便利店

## 2.2 日语表达强化

适合已经会日语，但希望提高：

- 主动检索速度
- 日常表达能力
- 口语反应速度
- 自然表达能力

## 2.3 碎片时间

单次学习应适合约 5～10 分钟。

不要求用户一次完成完整课程。

# 3. 产品核心原则

## P0 原则

### 3.1 核心流程优先

所有功能必须服务于：

**看 → 想 → 说 → 判断 → 听 → 唰**

能减少操作就减少操作。

### 3.2 主动回忆优先

用户回答前不能直接看到完整标准答案。

### 3.3 语音优先

语音输入是默认输入方式。

键盘输入是辅助方式。

### 3.4 一卡一表达

一张卡只训练一个主要表达。

### 3.5 快速反馈

回答后不进入独立结果页。

反馈直接显示在当前卡片。

### 3.6 不做考试感

不使用：

- 分数
- 扣血
- 生命
- 失败页面
- 强制重答
- 排行榜
- “回答错误！”等惩罚式文案

### 3.7 内容质量优先

优先保证：

**自然、实用、真实场景、值得说。**

不为了数量加入低价值表达。

# 7. 首页

## 7.1 首页目标

首页只解决：

**今天学多少、继续哪里、开始学习。**

首页不是 Dashboard。

## 7.2 页面结构

```text
日语唰唰唰                         ⚙

今日唰唰唰
12 / 20

       [ 开始唰 ]

最近学习
日常生活・家里
12 / 30

首页    牌组    收藏    我的
```

## 7.3 首页禁止项

**MVP 首页不显示“推荐题库”。**

不增加其他信息模块，除非后续明确修改 PRD。

## 7.4 今日学习

显示：

- 今日完成数量
- 今日目标数量

默认：

**20 张 / 天**

目标可设置：

- 10
- 20
- 30
- 50
- 自定义

目标是推荐值，不是硬限制。

完成不足不处罚。

## 7.5 开始唰

点击：

- 无学习记录 → 进入默认 / 当前牌组
- 有学习记录 → 继续最近学习位置

## 7.6 最近学习

显示：

- 牌组名称
- 牌组进度

例如：

```text
日常生活・家里
12 / 30
```

点击直接继续。

# 9. 学习卡片

## 9.1 页面目标

学习卡片是 MVP 核心页面。

核心操作：

**说完 → 得到反馈 → 唰下一张。**

## 9.2 默认布局

```text
┌──────────────────────────┐
│  12 / 20             ⋯   │
│                          │
│        ┌────────┐        │
│        │  图片  │        │
│        └────────┘        │
│                          │
│          冰化了           │
│                          │
│         氷が＿            │
│                          │
│         按住说话          │
│           ◯🎙     ⌨     │
│                          │
└──────────────────────────┘
```

## 9.3 信息层级

固定优先级：

**日语 > 图片 > 中文 > 操作提示**

## 9.4 顶部

左侧：

**今日进度，例如 12 / 20**

右侧：

**⋯**

不显示：

- 第几题
- 百分比
- 剩余题数

## 9.5 图片

用途：

**场景记忆锚点。**

建议：

- 宽度约 65～72% 屏幕宽度
- 圆角 16～20dp
- 不使用复杂解释
- 插画风格统一

## 9.6 中文提示

例如：

**冰化了**

建议字号：

**16～18sp**

视觉权重低于日语。

## 9.7 日语

例如：

**氷が＿**

建议字号：

**30～34sp**

使用 Medium / Semibold。

日语是页面主要视觉焦点。

# 10. 语音输入

## 10.1 麦克风

默认主操作。

设计要求：

- 圆形
- 约 72～80dp
- 稍大
- 易于按住

麦克风上方显示：

**按住说话**

提示文字较小。

## 10.2 按住

按住后：

```text
松开发送

   ◉
```

进入录音状态。

使用轻量呼吸 / 扩散动画。

## 10.3 松开

进入：

**识别中…**

## 10.4 识别失败

显示：

**没听清，再试一次**

然后回到录音状态。

识别失败不能判定为答错。

## 10.5 语音识别

MVP：

**语音 → Speech-to-Text → 文本答案判断**

Android 优先使用系统语音识别能力。

语音识别模块必须保持可替换。

# 11. 键盘输入

## 11.1 入口

麦克风旁显示：

**⌨**

只显示图标。

不显示：

- 打字
- 文字输入
- 键盘输入
- 切换输入方式

## 11.2 用途

键盘为辅助输入方式。

切换后：

- 显示文本输入框
- 用户输入日语
- 使用与语音相同的答案判断逻辑

语音仍是默认方式。

# 12. 答案判断

## 12.1 MVP 方案

```text
用户回答
 ↓
文本标准化
 ↓
accepted_answers 匹配
 ↓
正确 / 错误
```

## 12.2 标准答案

每张卡至少有：

```text
answer
accepted_answers[]
```

例如：

```json
{
  "answer": "氷が溶けた",
  "accepted_answers": [
    "氷が溶けた",
    "溶けた"
  ]
}
```

## 12.3 MVP 不做

- AI 语义判断
- 模糊语义匹配
- AI 对话
- AI 自动生成答案

数据结构需要为未来 AI 判断保留扩展空间。

直接在当前学习卡片显示反馈。

## 13.2 状态

```text

氷が溶けた

      🔊    ♡
```

## 13.3 行为顺序

```text
正确音效

 ↓

 ↓
自动播放标准语音一次
```

**约 0.8～1.2 秒。**

用户可点击：

- 🔊 再播放

# 21. 内容架构

## 21.1 表达簇

表达簇是内容组织单位，不直接作为学习 UI。

例如：

```text
表达簇：冰融化

氷が溶けた
氷が溶けている
氷が溶けそう
```

## 21.2 卡片

卡片是实际学习单位。

关系：

```text
表达簇
  ↓
多个相关表达
  ↓
卡片
```

原则：

**表达簇 = 组织**

**卡片 = 学习**

一个卡片可以属于多个牌组。

---

# 22. 内容标准

每张卡必须优先满足：

1. 自然
2. 实用
3. 有真实场景
4. 用户可能实际说
5. 适合主动回忆
6. 中文 → 日语存在检索价值

避免：

- 过度书面
- 文学表达
- 教科书式低频表达
- 为凑数量而添加
- 单纯孤立词汇

## 22.1 MVP 内容量

建议：

**30～50 张高质量卡片。**

MVP 不追求大内容库。

内容库后续持续扩充。

# 23. 音频标准

## 23.1 MVP

只提供：

**完整句子标准音频。**

## 23.2 自动播放

答对：

**自动播放一次。**

答错：

**自动播放一次。**

## 23.3 手动播放

点击：

**🔊**

重新播放。

## 23.4 MVP 不做

- 关键词单独播放
- 复杂循环
- 多种播放模式
- AI 自定义声音
- Voice Cloning

# 24. UI / 视觉标准

## 24.1 整体风格

- 干净
- 轻量
- 大量留白
- 圆角
- 柔和
- 稍微可爱
- 不幼稚
- 不教材化
- 不游戏化

## 24.2 UI 视觉锚点

核心锚点：

**日语文字 + 场景图片 + 圆形麦克风**

品牌锚点：

**海獭 🦦**

## 24.3 海獭使用原则

海獭只用于：

- 启动
- 空状态
- 识别失败
- 收藏为空
- 完成状态
- 少量轻反馈

不放在普通学习卡片中。

目的：

**建立品牌识别，不干扰学习。**

# 34. MVP 成功判断

第一版首先验证：

### 1. 用户是否愿意主动说

看到中文提示后，用户是否愿意按住麦克风回答。

### 2. 核心循环是否顺畅

```text
看 → 想 → 说 → 判断 → 听 → 唰
```

是否足够自然、快速。

### 3. 用户是否产生真实价值感

用户是否感觉：

**“以前知道但说不出来，现在真的能说出来了。”**

MVP 阶段不以：

- AI 数量
- 功能数量
- 内容数量
- 注册数量
- 商业化

作为首要目标。
